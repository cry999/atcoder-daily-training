# 監査付き改善ループ（2026-11-04）

## 比較の約束

起点は提出 #80582874 と main の `94ed887`。改善の単位を「仮説 → 費用の見積もり → 実装 → 同じ入力での比較 → 別担当の監査」とした。旧方式の細かな調整が飽和しても、構造を変える案を検討せずに全体を終了しない。実装担当と別の監査役が、表示の正しさ、紙の可視性、入力先読み、評価集合の使い方、停止理由を確認した。

操作の合法性は公式 tester、誤表示ゼロは全 1,024 注文の出力を読み切り、操作数の合計と公式スコアが等しいことの両方で確認する。不正操作でも tester の終了コードが 0 になる場合があるため、終了コードだけでは判定しない。

調整用は公式 seed 0–99。候補と設定を固定した後、未使用の seed 600–1099 を生成し、起点の解答と同じ入力で比較した。注文は 1 件ずつ読み、応答ごとに flush する。商品一覧からの期待値計算は使うが、未知の注文列は読まない。

## 起点の費用と別構造の比較

起点の 20 ケースを分解した 1 注文あたりの平均費用は以下。分類の合計は公式スコアと一致した。

| 要因 | 操作数 / 注文 |
| --- | ---: |
| 前ページの復帰 | 0.9990 |
| ページの取り出し | 4.5311 |
| 本体の補助紙 | 6.1143 |
| 新ページの挿入 | 1.0000 |
| 他の取っ手の色変更 | 6.0165 |

取っ手と取り出しの費用が大きいため、まずアクセス方法を変える案を試した。

| 仮説 | 実験・結果 | 判断 |
| --- | --- | --- |
| 白黒単独窓 128 枚＋疎な複数窓紙 64 枚で単調に表示を修正する | degree 3、beam 幅 8、seed 0 は 52,072、合法・誤表示ゼロ | このランダム辞書と探索方策は不採用。辞書型全般を否定しない |
| ページへ複数の取っ手を与え、ビーム探索でアクセスする | degree 3、14 取っ手、seed 0 は 30,139 | この方策は不採用。任意位置へ戻す別実装は不正操作があり、性能評価から除外 |
| 黒だけの複数取っ手＋専用窓から常時救出できる白コントローラ | 取っ手 8/12/16/24/32/40/48 × degree 1/2/3/4/8 × seed 0–2、各 10 万反復。最良は 16 取っ手、degree 1、平均 23,359 | 取り出しを短縮しても、黒い取っ手を見える状態へ戻す費用が増えた |
| 単独取っ手紙をページ直後に残し、露出を維持する | 同じ 105 ケース。最良平均 23,805.33。32 取っ手 degree 3 は 32,909.67 → 27,271 に改善 | 露出費用は減ったが起点には届かない |
| 白黒両側の補助紙を増やし、複数のページを候補にする | 静的な代替候補数を調査。最良の補正数から +2〜+4 に収まるページは平均約 1.0〜1.4 個 | 全候補数だけでは取り出し削減を見積もれない。実装優先度を下げた。これは静的代理評価 |
| 黒単独窓 64 枚＋全白紙＋黒い疎な辞書 127 枚 | ランダム辞書と楽観的な貪欲被覆でも degree 3 の被覆約 18.21 手、白紙 2 手、露出代理費用約 2.45 手 | 大幅改善を具体的に見込めず優先度を下げた。厳密な下界ではない |

白コントローラ案は、アクセス専用窓 1 個、黒取っ手 H 枚、本体補助紙 63−H 枚、白コントローラ 2 枚、商品ページ 127 枚で合計 192 枚。各商品に少なくとも 1 個の黒取っ手がある向きへ色を反転する。商品は 128 ペアから 127 クラスタへ統合するため、典型的には 126 ペア＋1 四商品クラスタとなる。

監査で「使わなかった白コントローラは常に末尾なので復帰は 1 手でよい」との仮説が出たが、その後ろへ退避した紙が存在することを確認し、監査役も撤回した。2 枚の復帰を含む実装の実測値を採用している。過去の複数取っ手案の不振も、方式全体の不可能性とは解釈しない。

## 採用した変更

アクセスを全面変更する案の測定後、既存構造で移動の戻し先を自由に選べる点を利用した。

1. 白黒交互の循環列を、隣接 2 枚が異色であるブロック列へ緩める。前ページを末尾へ送り続けず、対象のブロック直後へ戻す方式だけでも 100 ケース合計が 1,910,986 → 1,898,405 となった。
2. 色変更の 1 移動で、ブロック条件を保つ差し込み位置を全列挙する。商品数の多いページが手前に残る位置を選ぶ。
3. 取り出しで通過した範囲を、追加移動なしで重み順に組み直す。固定ペア設計でも 100 ケース合計 1,867,592。
4. 商品を 1–4 個の可変クラスタへ分ける。共通する黒を印刷し、商品の交換・移籍と窓の役割交換を同時に焼きなます。
5. 現在の補助紙の手数が最小になる候補に限り、次の 255 商品に対する平均補助紙費用で並べ方を選ぶ。現在と同一商品は次に来ない条件を反映し、同じ並びは重複評価しない。

最終設定は取っ手 16、本体 48、ページ 144、最大クラスタ 4、焼きなまし 300 万回。1,000 万回の候補は 100 ケースで 1,858,974 とわずかに良かったが、単独実行約 1.49 秒に対し採用版は約 0.48 秒。小さな改善より 2 秒制限への余裕を選んだ。なお、この比較は取っ手数等も異なる候補同士であり、反復数だけの効果ではない。

## 同手数での群再配置の検証

対象ページの元の順位を q とし、そのページを含むブロックまでの先頭範囲を組み直す。対象を先頭、反対色の重いページを相方とし、残りは白黒を組にして重み順に置く。動かす紙は元々対象より前にある q 枚だけ。

対象と、q が偶数ならその直後の元の相方を「配置済み」とする。元の q 枚を先頭から順に取り出し、望ましい並びで直前にある配置済みの紙の直後へ入れる。削除前のアンカー位置を、削除後の挿入深さに使う。この手順なら取り出す紙は常にグループの先頭で取っ手から見え、q 回の移動で望む並びになる。範囲より後ろの紙は変わらず、全ブロックの異色条件も保てる。

監査役がサイズ 2/4/6/8/10/12、全ブロックの色向き、全対象順位、乱数重み 1–4 を各 10 組検証し、12,840 例で可視性・完成順序・後続不変・ブロック条件を確認した。[独立検証コード](experiments/audit_rebuild.py)も保存した。実装担当側でも再実行した。

## 固定後の独立検証

| 集合 | 起点の合計 | 採用候補の合計 | 改善件数 | 誤表示・不正操作 |
| --- | ---: | ---: | ---: | ---: |
| seed 0–99（調整用） | 1,910,986 | 1,861,884 | 100 / 100 | 0 |
| seed 600–1099（固定後） | 9,560,818 | 9,314,954 | 500 / 500 | 0 |

独立検証で 245,864 手、2.5716% 削減。平均 19,121.636 → 18,629.908、範囲 18,256–18,981、1 注文最大 36 手。公式 tester を含む 6 並列で最大約 0.93 秒。最終ファイルのコンパイル後、seed 0 は 18,637、全商品巡回は 19,356、2 商品交互は 12,294、以前の代替処理用入力は 14,639。いずれも誤表示・不正操作ゼロ。以前の代替処理用入力でも今回の設計は成立するため、最後のケースを代替処理の動作確認とは数えない。

500 件では設計出力を保存していなかったため、単独窓方式の厳密な操作数を入力から再計算した。この方式は全白から初回商品までのハミング距離と、連続する商品のハミング距離の和に必ずなる。全 500 件で候補の実測値と異なり、代替処理が使われていないと確認した。新しい benchmark は出力の末尾 64 枚が穴だけかを直接記録する。全商品を同じ 32 黒のコードにした追加入力では割り当てが成立せず、代替方式が選ばれることも確認した。公式 tester の操作数 32、誤表示・不正操作ゼロ、fallback_designs=1 となった。対比較と厳密な代替費用は [CSV](validation-20261104.csv)、集計と全パラメータ比較は [JSON](audited-results-20261104.json)。

## 今回の停止判断と残る作業

旧方式のパラメータ調整だけで区切らず、別のアクセス方式、疎な辞書、白コントローラ、白黒補助紙を比較した。採用した構造でも、反復増加やクラスタ上限の変更による追加効果は小さくなった。監査役は、合法性の問題が見つからず、独立 500 件で改善を再現し、現時点で数手規模の改善を具体的に見込める未検証案が残っていないことから、候補の採用と今回のループを区切る判断を妥当とした。最適性を証明したものではない。

2026-11-04 07:36:00 JST にユーザーが [#80585705](https://atcoder.jp/contests/ahc074/submissions/80585705) を手動提出。提出ページの直接取得と Chrome 経由の読み取りは失敗したが、その後に提供された 07:39:59 の画像で、50 ケース全て AC、絶対スコア 932,253、実行時間 462 ms、メモリ 4,356 KiB、C++23 (GCC 15.2.0)、コード長 15,951 Byte を確認した。前回比 23,038 手、2.4116% 削減で、独立検証の改善率 2.57% に近い改善を本番でも確認できた。

07:40:50 の順位画像では 220 位、相対得点 25,821,192,046。以前の確認時点は 219 位だったが、確認時刻が違うため今回の解答変更だけに順位の差を帰属させない。100 位以内は未達。提出ソース自体は未取得のため、ローカルコードとの一致は未照合。今回の改善ループは伸びの低下を確認して終了し、次に再開する場合は新たな構造的仮説と改善余地の見積もりから始める。

## 比較実装の再実行

公式ツールを別途展開して使う。以下の controller と sparse は不採用の実験版。

```sh
c++ -O3 -std=c++17 ahc/ahc074_a.cpp -o /tmp/ahc074
python3 ahc/ahc074/benchmark.py /path/to/tools --executable /tmp/ahc074 --cases 100 --jobs 4
python3 ahc/ahc074/experiments/audit_rebuild.py
c++ -O3 -std=c++17 ahc/ahc074/experiments/controller.cpp -o /tmp/controller
# H、degree、反復数、補正重み、単独取っ手紙を保存するか
/path/to/tools/target/release/tester /tmp/controller 16 1 100000 1 0 < /path/to/tools/in/0000.txt
c++ -O3 -std=c++17 ahc/ahc074/experiments/sparse.cpp -o /tmp/sparse
```

静的代理評価の 2 本は引数に公式 tools ディレクトリを渡す。これらは合法な操作列を出す解答ではなく、探索優先度を考えるための評価。
